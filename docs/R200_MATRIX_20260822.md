# R200 十项延迟矩阵（2026-08-22/23，R1）

环境：Ubuntu 22.04 GNOME Wayland、librealsense 2.51.1 社区 R200 分支、
OpenCV 4.5.4、R200 官方固件 1.0.72.10。每项预热 10 秒、测量 60 秒、旋转
180°，sensor queue 与应用 latest slot 均为 1。设备序列号不写入仓库。

这是首轮功能/量级基线，不是最终参数结论。QVGA 和 Depth90 项是在识别修复后
补测，十项并非一次完全不间断的固定几何实验；每项也只有一次。正式决策仍须固定
显示器刷新率、曝光和几何位置后至少重复 3 次。

## 当前能下的结论

- VGA60 相比 VGA30 的首轮 median/P95 更低，且实际 callback 达到请求 FPS；
- 1080p30 实际只有约 23fps，median 超过 200ms，当前不适合作为低延迟默认档；
- QVGA 归一化检测修复后能稳定获得样本，但降低 RGB 分辨率没有比 VGA60 显示出
  明确延迟优势；
- 请求 VGA90/QVGA90 depth 的两项视觉 median 最低，因此按使用者决定把默认
  depth 请求改为 640×480@90；
- 但上述两项 depth callback 实际只有约 60fps，不能表述为“90Hz 已生效并导致
  延迟降低”。必须进一步查明组合流为何被限制在约 60fps并完成重复实验；
- Depth30/60 的 off/on 差异都小于单轮条件变化可能造成的误差，不能从 R1 宣称
  开启 depth 必然增加或降低固定毫秒数。

## 90/110 FPS 与 IR

R200 RGB 枚举最高 60fps；Depth 和两路 IR 枚举最高 90fps；所有 RS2/V4L2
profile 均没有 110fps。IR1 640×480@90 Y8 短测实际达到 90.27fps，但有效屏幕
圆点样本为 0，确认当前显示器不能用 IR 做圆点视觉延迟测试。

## 显示与 QVGA 修复

低于 VGA 的检测工作图现在保持宽高比并放大到至少 640×480，再使用官方 Hough
参数；QVGA 从 0 样本恢复到正式轮次 74/152 个样本。窗口的 RGB 预览改为彩色、
绿色识别框和等比 letterbox，只有用于编码时钟的圆点保持黑白。
